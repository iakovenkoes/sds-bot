# ATLANTIS • инструкция первого локального запуска для Windows

**Только для тестирования каркаса v0.2. Не публиковать ссылку на бот до приёмки всех функций.**

## Шаг 1. Docker Desktop
1. Установи Docker Desktop для Windows (обычно версия AMD64, если процессор Intel/AMD).
2. При запросе включить WSL 2/Windows Subsystem for Linux — следуй инструкции установщика и перезагрузи компьютер, если попросит.
3. Открой Docker Desktop, дождись надписи `Engine running`.

## Шаг 2. Распаковать код
1. Распакуй ZIP `ATLANTIS_bot_code_v0_2.zip`.
2. Открой папку `atlantis_bot`, где находятся `compose.yaml` и `.env.example`.
3. В проводнике Windows включи «Показывать расширения имён файлов», чтобы избежать файла `.env.txt`.

## Шаг 3. Секреты
1. В этой папке скопируй `.env.example` и переименуй копию в `.env`.
2. Открой `.env` через Блокнот или VS Code.
3. Заполни `BOT_TOKEN` — секрет из @BotFather, не присылай его в переписку.
4. Заполни `SUPER_ADMIN_ID` — свой **числовой** Telegram ID (получить можно у @userinfobot).
5. Придумай длинный пароль БД, вставь один и тот же пароль в обе строки `POSTGRES_PASSWORD` и `DATABASE_URL`.
   Пока выбирай пароль из латинских букв и цифр, без `@ : / # %`, чтобы не возникло проблем с URL.
6. `REVIEW_CHAT_ID` и `SUPPORT_CHAT_ID` пока оставь равными `0`. Функции этих групп ещё в разработке.

## Шаг 4. Запустить
1. Открой папку с `compose.yaml`.
2. В адресной строке проводника Windows напечатай `powershell`, нажми Enter — терминал откроется в этой папке.
3. Введи `docker compose up --build -d` и нажми Enter.
4. Проверь статус: `docker compose ps`.
5. Посмотреть логи: `docker compose logs -f bot`. Выход из просмотра — Ctrl+C (сам бот останется работать).

## Шаг 5. Открыть Telegram
1. Открой https://t.me/atlantis_sha26_bot.
2. Нажми `/start`. Майя должна отправить приветствие.
3. Через ~11–16 секунд должна прийти инструкция.
4. Проверь `/myid`, `/menu` и `/admin`, профиль и открытые по текущему времени разделы.

На 20 ноября регистрация на лекции по рабочему расписанию ещё закрыта — откроется 21 ноября. Для проверки календарных ограничений уже есть автоматические тесты. Не меняй время Windows, чтобы обойти ограничения.

## Шаг 6. Остановить
`docker compose down` — выключает бота и контейнер БД, но **сохраняет данные**.
**Не выполняй `docker compose down -v`**, иначе том PostgreSQL и данные удалятся.

## Если ошибка
- `docker compose ps` — работает ли `db` и `bot`.
- `docker compose logs --tail=80 bot` — ошибки Python/Telegram.
- `docker compose logs --tail=80 db` — ошибки PostgreSQL.
- Если видишь `Unauthorized` или `Token is invalid`, проверь токен **только в своём `.env`**.
- Если видишь `Conflict: terminated by other getUpdates request`, останови другую копию бота с тем же токеном.
- Отправляй мне скриншот ошибки **без токена, пароля и содержимого `.env`**.
