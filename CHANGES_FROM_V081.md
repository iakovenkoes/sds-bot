# ATLANTIS v0.10 — что изменилось относительно серверной v0.8.1

Сравнение выполнено с архивом `ATLANTIS_bot_code_v0_8_1.zip`. Эта сборка содержит также функции промежуточной v0.9.

## Новое в v0.10
1. **Рабочий планировщик сообщений.** Вместо неиспользуемого JSON теперь `app/scheduler.py`: автоматически создаёт адресные задания на отправку в постоянной таблице PostgreSQL `planned_messages`, затем отправляет их по московскому времени. Ключ `user_id + kind` не позволяет поставить одно и то же сообщение в очередь повторно. Состояние включения события сохраняется в `bot_settings`. При временном сбое Telegram отправка повторяется; в редких случаях прерывания между фактической отправкой и фиксацией в БД возможен дубль — не следует обещать математически «ровно один раз».
2. **9 событий в расписании:**
   - 22.11 14:00 — лор 1 (всем пользователям);
   - 23.11 15:10 — напоминание PR (активно зарегистрированным на 23.11);
   - 24.11 13:30 — лор 2 (всем);
   - 24.11 15:10 — напоминание ER (активно зарегистрированным на 24.11);
   - 25.11 15:10 — напоминание партнёрки (активно зарегистрированным на 25.11);
   - 27.11 16:00 — лор 3 (всем);
   - 27.11 18:00 — дедлайн первых трёх блоков (только участникам выезда);
   - 28.11 10:00 — открытие «Погружения» (только участникам выезда);
   - 28.11 18:00 — напоминание «Погружение» (только участникам выезда).
   В **12:10** 23, 24 и 25 ноября информация о спикере раскрывается **только в карточке лекции**, массовой рассылки в 12:10 и старого анонса в 11:30 **нет**.
3. **Тексты и оформление** для дропов и напоминаний берутся из `ответы майи .docx`: сохранены абзацы и HTML-акценты; в лекционных напоминаниях динамически подставляются реальные темы и аудитории 346/346/246, адрес Кантемировская, 3к1.
4. **Досылка лора новым пользователям** — только при первом `/start`, если соответствующий сюжетный дроп уже прошёл. Последовательно с интервалом 12 секунд, после инструкции. После конца выезда не досылается.
5. **Пропущенные по причине поздней установки события** (>30 мин после назначенного времени) не отправляются внезапно всем, а получают отметку `skipped_late`. В таком случае необходима ручная отправка.
6. **Новая команда супер-администратора** `/schedule_status` — видит 9 событий, очередь и количество успешных отправок. Сами сообщения участникам без установки кода на сервере не отправятся.
7. **Фильченкова Анастасия Сергеевна** добавлена в `data/attendee_whitelist.json`. Теперь 81 уникальное имя. Для указанного `SUPER_ADMIN_ID` кнопка «Путь героя» доступна в меню даже если ФИО ещё не введено; ограничения по датам на блоки остаются.

## Включено из v0.9 (в сравнении с v0.8.1)
- Группа проверки работ: `/bind_review`, четыре `/bind_stage`, `/review_status`, `/review_sync`.
- Роль `reviewer`: `/addreviewer ID`, `/removereviewer ID`, просмотр списка; не выдаёт прав `/admin`.
- Распределение работ по темам, кнопки принять/отклонить, защита от двойной проверки и начисления.
- Ответы через Reply в группе вопросов для обычных администраторов (`admin`) и супер-администратора без дополнительной роли `support`.
- Инструкция этих функций: `UPDATE_TO_V09.md`.

## Не изменилось
- Список из семи обычных администраторов, права супер-администратора через `.env`, срочные рассылки с подтверждением, карточки «Пути героя», регистрация на лекции, основные тексты, видеокружочки, группа вопросов.
- Кодовые слова и счастливые билеты **пока не реализованы полностью**, тесты этих функций не проводились.

## Важное ограничение
38 автоматических тестов пройдены, 2 пропущены из-за ограничений тестового окружения. Реальный запуск Telegram и PostgreSQL на вашем сервере этим не подтверждён. Обязательно провести пробный запуск и проверить `/schedule_status`, регистрацию, поддержку и группу проверки. Не запускать одновременно две копии polling-бота с одним токеном.
