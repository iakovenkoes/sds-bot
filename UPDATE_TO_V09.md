# ATLANTIS v0.9 — обновление существующего сервера

## Что изменилось

1. **Группа проверки «Пути героя»:** `/bind_review` в теме General; далее по одной команде `/bind_stage архив`, `/bind_stage разведка`, `/bind_stage сборка`, `/bind_stage погружение` в соответствующих Telegram-темах. Данные привязки записываются в PostgreSQL (`bot_settings`).
2. **Проверяющие без админки:** супер-администратор выдаёт отдельную роль командами `/addreviewer <telegram_id>` и `/removereviewer <telegram_id>` в личном чате с ботом; `/reviewers` показывает список. Проверяющий должен сперва отправить `/start` боту, а затем вступить в закрытую группу проверки обычным участником. Он не получает доступ к `/admin`.
3. **Маршрутизация работ:** после сдачи карточка и вложения (текст, фото, видео, видеокружочки, файлы) поступают в нужную тему. Кнопки «Принять»/«Отклонить» работают только у роли `reviewer` (и главного администратора). Принятая работа начисляет все баллы ровно один раз, отклонённая — 0. Решение не отправляется участнику. В журнале фиксируется проверяющий.
4. **Отложенные работы:** если группа или тема не привязана, сданная работа остаётся в `pending`; после привязки в General отправить `/review_sync`, чтобы переслать ранее не доставленные работы (до 100 за вызов). `/review_status` показывает, какие темы подключены и сколько работ ждут пересылки.
5. **Исправление группы вопросов:** обычные администраторы из `/addadmin ID` теперь могут отвечать на обращения в группе Reply и пользоваться кнопками поддержки. Роль `support` отдельно тоже продолжает работать; другие участники группы — нет. Отправка через Reply доступна при ответе на сообщение бота, связанное с обращением. Проверяющие без админки права поддержки не получают.
6. **Исправление результата проверки:** супер-администратор может исправить завершённый результат в личном чате: `/review_override НОМЕР_РАБОТЫ accept` или `reject`; баллы корректируются компенсирующей записью.

### Команды по порядку

**В группе проверки**, только со своего Telegram-аккаунта супер-администратора:

1. В General: `/bind_review`
2. В теме «Архив»: `/bind_stage архив`
3. В теме «Разведка»: `/bind_stage разведка`
4. В теме «Сборка»: `/bind_stage сборка`
5. В теме «Погружение»: `/bind_stage погружение`
6. В General: `/review_status` и `/review_sync`.

**В личном чате супер-администратора с Майей**: `/addreviewer 123456789`, `/reviewers`, `/removereviewer 123456789`. Отдельная роль `reviewer` не выдаёт административных полномочий.

**В группе вопросов** существующая `/bind_support` остаётся прежней. Администратор отвечает на сообщение Майи с вопросом через Telegram Reply. Если сообщение не доставляется, проверить, не закрыто ли обращение, есть ли права `admin`, а затем `docker compose logs --tail=150 bot`.

## Установка / обновление Docker

1. Сохранить `.env` (его нет внутри ZIP), а также выполнить резервную копию **PostgreSQL**, прежде чем обновлять приложение. Пример с работающего серверного окружения: `docker compose exec -T db pg_dump -U atlantis -d atlantis -Fc > atlantis_before_v09.dump`. Пароли/токены не публиковать.
2. Заменить файлы проекта из архива, **не удаляя `.env`** и Docker-том с PostgreSQL. Текущий файл `compose.yaml` не нужно менять, если сервер использует собственный Compose-файл с внешней БД.
3. В каталоге проекта: `docker compose up -d --build`.
4. Проверить: `docker compose ps` и `docker compose logs --tail=150 bot`. Команды `/start`, `/admin`, `/admins`, `/bind_support`, `/bind_review` и маршруты проверки проверить в Telegram.

**Не выполнять** `docker compose down -v`, `docker volume prune` и не удалять базу. В версии v0.9 добавляется таблица `review_deliveries` без удаления и изменения существующих таблиц; при старте приложения она создаётся через `Base.metadata.create_all`. Для дальнейшего production-развития необходимы миграции (Alembic).

## Важно перед публичным запуском

- Не запускать второй экземпляр бота с тем же токеном в polling одновременно с серверным.
- Запуск на реальном сервере и отправка реальных Telegram-сообщений **не тестировались в этой среде**. Проект проходит локальные статические и независимые модульные проверки; обязательно пройти интеграционный сценарий в Telegram со **вторым тестовым аккаунтом**.
- Отдельно остаются незавершёнными/не проверенными в production: расписание массовых сюжетных рассылок, механизм кодовых слов, счастливые билеты. Не считать бот готовым к публичному запуску, пока эти функции не будут завершены.
- Исправление результата проверки по `/review_override` пишется в журнал баллов; оно не изменяет историю сообщений Telegram в группе.
- Если сеть Telegram не примет пересылку одного из вложений, в теме появится предупреждение: не принимать решение по такой работе до исправления доставки.
