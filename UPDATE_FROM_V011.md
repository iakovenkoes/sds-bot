# ATLANTIS v0.12 — срочная рассылка с выбором получателей

## Обновление поверх v0.11 (или напрямую поверх v0.8.1)

Полный проект сохраняет функции v0.11 (ответы на вопросы, группа проверки заданий, роли проверяющих, кодовые слова, счастливые билеты, автоматические сюжетные сообщения). В v0.12 изменена логика **срочных** рассылок: при выборе кнопки в `/admin` администратор сперва выбирает аудиторию.

### Кому можно отправить
1. Всем пользователям, которые запускали бота.
2. Только **подтверждённым** участникам выезда: ФИО сопоставлено со списком, Telegram ID привязан к записи `trip_attendees.telegram_id`.
3. Тем, кто записан хотя бы на одну лекцию (только активные регистрации).
4. Записанным на PR 23.11.
5. Записанным на ER 24.11.
6. Записанным на партнёрку 25.11.

**Внимание:** участник из списка выезда, который ещё не открыл бота или не привязал ФИО к Telegram, не попадает в адресную рассылку. Это безопасное ограничение. Бот показывает точное число получателей до подтверждения. Для включения в целевую группу участник должен выполнить идентификацию по ФИО в боте.

Администратор выбирает аудиторию → присылает одно сообщение (текст, фото, видео, кружочек, документ) → видит предпросмотр, аудиторию и число получателей → подтверждает отправку. Форматирование копируется Telegram API. Подтверждённая рассылка отправляется только выбранной аудитории. Отмена возможна на любом этапе. Отчёт об отправке появляется в чате и для обычного админа дополнительно отправляется супер-администратору.

Для аудита тип аудитории записывается в существующую таблицу `bot_settings` под ключом `urgent_audience:<ID>`, поэтому **изменений структуры PostgreSQL и отдельной миграции нет**.

### Установка на сервере
- Перед заменой сделать резервную копию PostgreSQL.
- Не удалять базу, Docker volumes или `.env`. **Не использовать `docker compose down -v`.**
- Остановить старый экземпляр polling (один токен — один работающий экземпляр).
- Развернуть новую папку проекта и сохранить старый `.env`.
- Выполнить из папки с `compose.yaml`: `docker compose up -d --build`.
- Проверить `docker compose logs --tail=100 bot` и команды `/admin`, `/schedule_status`.
- Без отправки настоящей рассылки проверить последовательность: `/admin` → Срочная рассылка → выбрать аудиторию → набрать тест → предпросмотр → **Отмена**.
- Для функционального теста выберите аудиторию с собственным тестовым Telegram-аккаунтом; отправка реальная, отменить после подтверждения нельзя.

### Ограничения и примечания
- Списки получателей выбираются во время выбора аудитории и хранятся в FSM до подтверждения; если регистрации изменились за время составления сообщения, начните рассылку заново.
- Пока бот использует `MemoryStorage` для незавершённого диалога отправки: после перезапуска нужно заново выбрать аудиторию. Уже отправленные записи остаются в PostgreSQL.
- Не отключать автоматические сюжетные сообщения: они работают отдельно от срочных.
- Не изменяются семь штатных admin ID и главный администратор в `.env`.
- Перед публичным использованием обязательно провести Telegram+PostgreSQL проверку на сервере; статические тесты не гарантируют доставку.
