# ATLANTIS v0.10.1 — обновление поверх работающей v0.8.1

**Источник:** полный код v0.8.1 + функциональность v0.9 и v0.10, плюс исправленный предпросмотр супер-администратора на сервере. Устанавливать промежуточные версии НЕ нужно.

## Новое относительно v0.8.1
1. **Лор и напоминания по московскому времени**: в `app/scheduler.py` планировщик, запускаемый в `app/main.py`, с очередью в PostgreSQL. 9 событий в `data/scheduled_messages_agreed.json`: 22.11 14:00, 23.11 15:10, 24.11 13:30, 24.11 15:10, 25.11 15:10, 27.11 16:00, 27.11 18:00, 28.11 10:00 и 28.11 18:00 (все МСК). Дропы — всем, напоминания о лекциях — зарегистрированным, сообщения о заданиях — только подтверждённым участникам выезда. В 12:10 23–25 ноября тема и спикер раскрываются в карточке лекции, **без рассылки**.
2. **«Путь героя»**: список из 81 человека включает `Фильченкова Анастасия Сергеевна`. Суперадминистратору, чей ID прописан в `.env`, раздел виден независимо от заполненного ФИО. Для просмотра **закрытых по датам** заданий можно включить `/preview` прямо на сервере, даже при `TEST_MODE=false`. Это исключительно ручная команда супер-администратора; `/participant` выключает предпросмотр, `/admin` тоже выключает. ВАЖНО: если сдавать работу в режиме предпросмотра на рабочем сервере, она попадёт в настоящую БД — просматривайте задания без сдачи.
3. **Роли**: семь обычных администраторов из `data/initial_admin_ids.json`, главный админ — `SUPER_ADMIN_ID` из `.env`. `/addadmin ID`, `/removeadmin ID`, `/admins` разрешены только главному. В группе вопросов Reply могут отправлять обычные и главный администраторы.
4. **Проверка работ**: `/bind_review` в General; `/bind_stage архив`, `/bind_stage разведка`, `/bind_stage сборка`, `/bind_stage погружение` в одноимённых темах; `/review_status`, `/review_sync`. В личном чате суперадмина: `/addreviewer ID`, `/removereviewer ID`, `/reviewers`. Проверяющие без доступа к `/admin`. Принять/отклонить можно один раз; зачёт автоматически начисляет баллы.
5. **Срочные рассылки** сохраняются: `/admin` → «Срочная рассылка» → предпросмотр → подтверждение.
6. **Контроль расписания**: `/schedule_status` показывает статусы и статистику рассылок супер-админу.

## Безопасное развёртывание
1. Разработчик делает резервную копию существующей PostgreSQL (`pg_dump`) и сохраняет текущие `.env`, файлы конфигурации, названия/путь Docker volume. НЕ заменять `.env` файлом `.env.example`.
2. Проверяет, что новый `compose.yaml` будет ссылаться на **ту же БД/том**, что уже используется v0.8.1. Имя проекта Docker Compose может изменить имя volume при переносе в новую папку! При необходимости задать старое имя проекта `docker compose -p ИМЯ_ПРЕДЫДУЩЕГО_ПРОЕКТА ...` либо явное имя существующего volume.
3. Останавливает старый процесс polling и обновляет код бота: `docker compose up -d --build` из папки проекта; не использовать `down -v`.
4. Проверяет `docker compose ps` и `docker compose logs --tail=150 bot`; БД и бот должны быть активны. Права в PostgreSQL сохраняются.
5. С аккаунта `SUPER_ADMIN_ID` проверить в Telegram `/admins`, `/admin`, `/menu`, `/preview`, `/participant`, `/schedule_status`.
6. Подключить ранее созданную группу проверки и четыре темы указанными выше командами. Повторно подключить группу вопросов через `/bind_support`, если её ID не перенёсся из старой БД.
7. Проверить Reply администратора из группы вопросов, а затем тестовую сдачу и проверку работы (для тестов желательно отдельный бот/БД).

## Важные ограничения
- Описание событий в JSON и прохождение тестов ещё **не доказывают** фактическую отправку в Telegram. Нужна работающая серверная v0.10.1, действующий токен, часовой пояс и доступ к Telegram API. Подтверждение — `/schedule_status` и логи после события.
- События, которые уже прошли более 30 минут назад к первому запуску версии, помечаются `skipped_late`, а не отправляются всем задним числом.
- Система кодовых слов и счастливых билетов не завершена; не обещайте начисление за них до отдельной проверки.
- При изменении структуры существующей БД в будущем понадобятся полноценные миграции Alembic: сейчас новые таблицы создаются автоматически, но изменение существующих колонок — нет.
- Только один запущенный polling-процесс на токен бота.
